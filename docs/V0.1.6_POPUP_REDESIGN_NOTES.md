# CookieGate v0.1.6 — Popup redesign (design D) notes

Status: TEST BUILD — pending real-browser confirmation before store packaging.
Packages: `dist/cookiegate_v0.1.6_firefox_TEST.zip` (MV2), `dist/cookiegate_v0.1.6_chrome_TEST.zip` (MV3),
Chrome unpacked: `dist/chrome_v0.1.6_unpacked_newUI`.

## What changed
- New popup (`ui/popup.html`, `ui/popup.css`, `ui/popup.js`) implementing design D: answers-first summary card,
  Trusted→Strict slider, search that replaces the Domains tab, ring chart only in the Browser tab, light/dark switch.
- New `ui/cg_engine.js`: one engine for classification, policy, root-domain handling, removal and export shapes.
- Old popup files are no longer packaged (`cookiegate.polish.css`, the 7,600-line router popup). Rollback source:
  `dist/patch_v0.1.2/firefox/ui/popup.js` (v0.1.5).
- Background scripts and the banner suppressor are unchanged.

## Behavior that needs your sign-off (not silent)
1. **One classifier instead of four.** Before v0.1.6 the popup Active Site, popup Browser Observer, popup router and
   Chrome service worker each classified cookies differently (e.g. `_ga` was "unknown" on Active Site but "tracking" in
   the service worker). v0.1.6 uses the union of all of them, logins/security checked first, plus a vendor table.
   Proven: every cookie any old classifier treated as login/security is still protected (23/23 cases).
   Effect: 73 of 155 test names changed category — mostly unknown → tracking with a named source (Google, Meta, Adobe,
   Chartbeat, Piano, Microsoft, TikTok, Snap, Reddit, Pinterest, Hotjar…) and consent cookies → preferences.
   Full table: run `node dist/v0.1.6_tests/engine_parity_tests.mjs`.
2. **Mode semantics follow the service worker engine exactly** (it was the only complete policy engine).
   Trusted removes nothing via Clean (the earlier mockups said "only trackers" — that was mock data).
   Strict keeps unknown first-party cookies "for review" rather than deleting them.
3. **Root domain = registrable domain (eTLD+1 heuristic).** `edition.cnn.com` now inspects `cnn.com` and its
   subdomains, matching the stated Domain Ops rule. Previously only `www.` was stripped.

## Preserved contracts
- Storage: `cookiegateGlobalMode`, `cookiegateSiteModes`, `cookiegateKeepRules`, `cookiegateEvidenceLog`
  (extension storage); `cookiegate.globalMode`, `cookiegate.siteMode:<host>`, `cookiegate.domainRules.v1` (localStorage).
  Upgrading users keep their saved modes (tested).
- Evidence records: same shape as the service worker (`event_type, event_id, timestamp_utc, payload`);
  `cookiegate.cookie.delete.v1` per removed cookie (reasons: `manual-clean`, `manual-wipe`, `manual-clean-all`),
  `cookiegate.policy.site_mode_set.v1 / site_mode_cleared.v1 / global_mode_set.v1 / keep_rule_set.v1`.
- Exports: `cookiegate.browser_observer.v3` (same fields; additive `classification_detail`, `vendor`, `engine`) and
  `cookiegate.site_package.v1`. Raw cookie values are never exported (tested).
- Safety: nothing is deleted without an explicit tap (Clean needs two taps; Wipe and Clean-all use a confirm sheet);
  logins/security cookies are never removed unless the user ticks "also remove logins".

## Moved or removed surfaces
- Evidence log viewer and Diff Inspector panels are not shown (evidence is still recorded and included in the
  site report export).
- Domain Ops "registry" options (cache / local storage / IndexedDB / service workers per domain) are replaced by
  "Always use <mode> on <site>". Browser-wide cache clearing remains under Browser → Clean all sites.
- Banner suppression appears as a small "N cookie banners hidden on this site" line on the summary card.
